# Processed data and accuracy reviews

`sample_investors.csv` is generated by `python -m backend.pipeline`. It is
header-only until CIKs are configured in `data/seeds/seed_ciks.csv`; do not add
fabricated or unverified investor rows.

To audit data accuracy, add one row per independently checked field to
`verification_sample.csv` using this schema:

```csv
cik,field,verified_value,source_url,verified_at
```

- `cik` must identify a current record in `sample_investors.csv`.
- `field` must be one of `name`, `latest_filing_date`, `latest_filing_form`,
  `is_active`, `aum_usd`, `check_size_min_usd`, `check_size_max_usd`, or
  `target_sectors`.
- `verified_value` is the value confirmed from the cited source. Use ISO
  `YYYY-MM-DD` for dates, `true`/`false` for activity, and `|`-separated sector
  names for sectors. Numeric values are compared numerically; text comparison
  ignores case and repeated whitespace.
- `source_url` must be an HTTPS URL to the source used for the independent
  check, and `verified_at` must be an ISO date.
- A CIK/field pair may appear only once. The API rejects malformed checks and
  excludes reviews for CIKs no longer present in the active export.

Accuracy is the percentage of checked fields that match the stored investor
value. `accuracy_sample_size` and `verified_records` count distinct reviewed
CIKs. Keep the sample independently checked and update it when the compared
investor data changes.
